O que é a página do Pact Broker?

A URL do contrato é o acordo publicado entre portal e API — não é um relatório de execução do Vitest. Cada bloco lista um request/response que o consumer depende. O provider ainda precisa verificar se a API real responde igual.

Abrir contrato no Pact Broker (localhost:9292)

Como saber se passou ou falhou

1. Consumer test — “o cliente está correto?”

Roda localmente, sem rede para a API real. Usa mock do Pact.

Comando: npm run test:pact:consumer

ResultadoOnde ver
PassouTerminal: 5 passed
FalhouTestes vermelhos, exit code ≠ 0
PublicadoBroker exibe versão e interações
2. Provider verify — “a API honra o contrato?”

Repete os 5 requests contra UAT/SIT. Responsabilidade do time de backend.

Comando: npm run pact:verify-provider (URL + token)

ResultadoOnde ver
PassouBroker: verified / verde
FalhouBroker: vermelho + diff
Hojeunknown — verify não executado

O que cada teste valida (e o que não valida)

Valida
  • Método, path e query params acordados
  • Header Authorization: Bearer nos cenários autenticados
  • Status 200 / 401 e Content-Type: application/json
  • Formato JSON: items[], page, pageSize, total
Não valida
  • Lógica de negócio completa
  • Dados reais do banco (matchers flexíveis)
  • Performance, UI ou fluxo E2E do usuário
Mensagem para gestão

Consumer tests já passaram e o contrato está publicado. O passo pendente é provider verification: sem ele, o Broker mostra o acordo mas não confirma que a API em UAT ainda cumpre o combinado.
